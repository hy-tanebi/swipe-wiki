# Swipe Wiki 要件定義(①)

## なぜ作るか

- 技術記事を自分から探しに行って1つ1つ中身を確認する工数を減らしたい
- 記事は自動で取得し、ユーザーは「残す / 捨てる」の判断だけをすればよい状態にする

## MVP(これだけで課題は完了)

- ユーザーは、未判定の記事を1件ずつカードで見て、右=残す / 左=捨てる を選べる
- ユーザーは、残した記事の一覧を見ることができる
- ユーザーは、一覧のタイトルから元記事(外部URL)へ飛ぶことができる

## 余裕があれば(MVPが動いて時間が余ったら。優先順)

1. 一覧のソート(残した日時順 / 公開日順)
2. 一覧から外す(判定を「捨てる」に変更する。記事は消さない)
3. カテゴリ
4. お気に入り
5. 定期取得(MVPは手動実行)
6. 取得元に Zenn を追加

## やらないこと

- 記事の本文は保存しない(外部URLへのリンクのみ)
- 他者への共有機能
- 記事の編集・メモの追加
- 複数ユーザー(1人用・認証なし)

## 記事の取得元と項目

- 取得元: **Qiita API v2**(MVPはこれのみ)
- 項目: タイトル / URL / タグ(カンマ区切り文字列) / 公開日 / 取得元

## 技術スタック

- フロントエンド: React
- API: FastAPI(Python)
- DB: PostgreSQL(ローカルは Docker Compose、本番は Cloud SQL)
- デプロイ: Docker → Cloud Run(GCP)

## 設計上の申し送り(②〜④で使う)

- 「未判定」= swipes テーブルに判定レコードがない記事
- 「捨てる」も判定として保存する(記事は削除しない)。課題文の `POST /swipes で保存` に合わせる
- 同じ記事を二重取得しないよう、URLをユニークにする
- タグは配列で返るため、保存前にカンマ区切りに変換する
- 画面は2枚(スワイプ画面 / 一覧画面)。3枚目が必要になったらスコープ漏れ
